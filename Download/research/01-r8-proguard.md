# R8 / ProGuard obfuscation — APK-only feasibility

**Finding:** Not a safe, general-purpose selectable protection for an arbitrary already-built APK when the utility has only the APK and no build inputs. R8/ProGuard-style obfuscation is fundamentally a build-time transformation. R8 consumes Java class files and produces optimized DEX; it is not a general APK-in/APK-out obfuscator. An APK normally contains DEX, not the original Java/Kotlin source or class-file/build configuration needed for the normal R8 pipeline. A DEX-level reverse-engineering/rewrite/repack pipeline would be a different post-build technique, with substantial compatibility and signing risks—not a drop-in R8 option.

## Evidence

- **R8 repository — “R8”** ([Google source](https://r8.googlesource.com/r8/)): Google describes R8 as a whole-program shrinker/minifier that “consumes class files” and outputs DEX (or class files); its example invocation needs a ProGuard config, Android SDK `android.jar`, and program JAR input. Supports the input/output and build-pipeline distinction.
- **Android Developers — “Enable app optimization with R8”** ([link](https://developer.android.com/topic/performance/app-optimization/enable-app-optimization)): R8 removes unreachable code, optimizes, and renames identifiers. Android documents enabling it in the app’s release build configuration and supplying keep rules; recommends optimizing the final version that is tested before publication. Supports build-time nature, configuration needs, and validation requirement.
- **Android Developers — “Fix optimization problems”** ([link](https://developer.android.com/topic/performance/app-optimization/troubleshoot-the-optimization)): R8-induced crashes are typically caused by broken reflection; the documented remedy is adding keep rules. It also explains that R8 changes names/line numbers and a `mapping.txt` is needed to retrace stacks. Supports compatibility and operational risks.
- **OWASP MASTG — “MASTG-KNOW-0033: Obfuscation”** ([link](https://mas.owasp.org/MASTG-KNOW-0033/)): R8/ProGuard rename classes, methods, and fields during the release-build process; behavior is controlled by release-build configuration and keep rules. Supports that this is configured obfuscation, not an automatic runtime wrapper feature.

## Requirements and limits

For a normal R8/ProGuard build, provide the app's compiled Java class files (source itself is not strictly required), relevant dependencies/classpath and Android platform library/target API information, a program/build configuration (including entry points and keep rules), and access to the release build/repack/signing pipeline. Preserve the exact mapping file for diagnostics and test the optimized result on supported devices. The build must know what code is reachable and what names must remain stable.

With only an arbitrary APK, its DEX cannot simply be fed to R8 as ordinary class-file input. Recovering or converting DEX to class files, inferring dependencies/configuration/entry points and reflection usage, then rebuilding resources, manifest, DEX, and signatures is not a generic semantics-preserving R8 workflow. Even if a separate DEX obfuscator is used, dynamic reflection, JNI/native method names, serialization, WebView JavaScript interfaces, manifest component names, resource lookups, plugins, and external callers can depend on identifiers that static analysis cannot reliably discover. Overly broad keep rules reduce obfuscation; overly narrow rules can break behavior. Re-signing also changes the APK signer and may affect signature-based integrations or updates.

## Recommendation

Do **not** expose this as an active R8/ProGuard option for the stated APK-only utility. It is appropriate as a source/build-integrated option when the user supplies the build inputs and can configure keep rules, retain mapping files, sign, and test. A separate, explicitly labeled post-build DEX transformation could be evaluated independently, but it must not be described as R8/ProGuard and cannot promise compatibility for arbitrary APKs. The existing `AppComponentFactory` wrapper does not supply the missing R8 program inputs or make obfuscation a runtime operation.
